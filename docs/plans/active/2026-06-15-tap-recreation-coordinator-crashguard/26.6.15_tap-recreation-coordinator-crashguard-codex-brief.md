## Context

FineTune is a macOS (Tahoe / macOS 26) per-app audio utility. Today, tap recreation is driven by **two overlapping, state-clobbering mechanisms** (a `serviceRestartTask` path and a reentrancy-prone `recreateAllTaps`/permission-fallback path) that can snapshot *after* restart-time device churn, race on suppression flags, and strand routing on devices that vanished during a CoreAudio service restart. Separately, the `CrashGuard` SIGABRT/SEGV signal handler calls HAL/IPC/locks from async-signal context — unsafe.

This run replaces both recreation mechanisms with **one serialized recreation transaction** owned by `AudioEngine` (snapshot + suppress + cancel **before** churn → drain in-flight switch work → recreate/probe → **awaited** restore + reconcile-on-close → clear suppression), folds in permission-driven mute, and removes the crash-time HAL cleanup (relying on next-launch `OrphanedTapCleanup`).

**The plan is the contract.** It was hardened across one adversarial-agent cycle and three user review cycles, and **Gate-5 signed** (see `critique-log.md` cycle 3.5). Every `file:line` reference in the plan was verified at the source. **Read `chain_plan_file` in full before starting, and re-read each task's section immediately before implementing it.** This brief carries the *run discipline*; the plan carries the *per-task contract, file lists, and verified line refs*. ## Escalation policy — act, pivot, surface, continue

Three tiers, ordered by intrusiveness: **ACT** (smallest — fix mechanical issues inside the slice's stated contract), **PIVOT** (middle — reframe a brittle or unmeasured piece of the contract when measurement proves it was structurally unreachable), **SURRENDER** (largest — design judgment the user must make, OR acceptance genuinely cannot be satisfied even with a small reframe).

Default: ACT or PIVOT and surface in the commit body. Don't surrender on mechanical calls. Don't surrender on brittle preconditions a small reframe solves.

### ACT (don't surrender) when ALL hold:
- The slice's stated acceptance is still fully satisfied after the deviation.
- The deviation is mechanical, not a design call.
- The deviation is documented in the commit body (reason + which allowed-file list it expanded).

Specific ACT cases:
- Mechanical bug fix outside slice scope (off-by-one, wrong constant, missing import, a drifted `file:line` ref in the plan vs. the real source) required for the slice's acceptance to pass. Fix in the same commit; note the drift.
- Pointer/doc hygiene spreading to 1–3 nearby docs the slice's edits left stale. Sweep in the same commit. (For T8 this is the slice's whole job — grep-driven.)
- Test red-phase fails to fire because production already satisfies the contract. Add the regression test anyway; the commit body documents the manual revert-to-verify-red attestation.
- **Unrelated phase-boundary red.** A broad `swift test` reports a failure in test code whose exercised production paths do NOT intersect this run's cumulative `git diff --name-only <run-start-HEAD>..HEAD`.

  Discrimination protocol (run BEFORE consuming sustained-red budget):
    1. Read the failing test's imports + assertions to identify the production paths it exercises.
    2. Compute `git diff --name-only <run-start-HEAD>..HEAD`.
    3. If the failing test's covered paths are disjoint from the run's modified paths, this is unrelated noise.
    4. Verify the slice's own targeted `--filter` lanes (every file the slice changed) are GREEN — that is the slice's actual acceptance signal. The broad gate is supplementary.
    5. ACT: document the unrelated red (test name + one sentence on what it covers + why it's out of scope). If it looks like a real isolation flake (passes alone, fails in broader context), add a one-line note in `docs/known_issues/`. Continue with slice-targeted gates.
    6. Do NOT consume the sustained-red budget. Do NOT consume an ACT slot — this is the contract executing as designed.

  Does NOT apply when: the failing test exercises files this run modified (real breakage — e.g. `AudioEngineRoutingTests`, `DeviceRoutingTests`, `AudioSwitchingTests`, `SettingsManagerRoutingTests`, `StartupAudioInterruptionTests` all exercise `AudioEngine`/`SettingsManager` paths this run heavily edits, so treat their failures as REAL); the slice's own targeted lanes are also red; or the diff plausibly affects shared infra the failing test depends on. When in doubt, treat as related and fix.

### PIVOT (reframe brittle contract, continue) when ALL hold:
- The slice's CORE INTENT is still satisfied — only an EDGE (a numeric threshold, expected value, tolerance, parameter, timeout) is structurally unreachable as written.
- Mechanical evidence proves the original contract was unmeasured / aspirational / extrapolated. "Mechanical evidence" = a measurement/diagnostic the commit body can record.
- The reframed contract preserves the same TYPE of coverage the original provided.
- The reframe introduces no design change the user might disagree with.
- Documented as `PIVOT — <reason>` in the commit body with: (a) original contract verbatim, (b) the measurement that proved it unreachable, (c) reframed contract, (d) one sentence on why the reframe preserves intent.

The dispositive PIVOT question: "Did the author specify this edge with measurement, or extrapolate/aspire? If they extrapolated, can a small reframe preserve the slice's coverage?" If yes → PIVOT. (For this plan, the most likely PIVOT site is a timing assumption — e.g. `serviceRestartDelay = .zero` not fully draining a continuation in one clock advance; reframe to an explicit drain/await point rather than a fixed sleep.)

### SURRENDER (write SURRENDER block, halt) when ANY hold:
- The deviation needs DESIGN judgment the user must make (new public API shape, new semantics beyond the plan's stated seams, refactor-scope decision, choice of metric/algorithm/library).
- It would touch a public contract the user might disagree about, or any "Prohibited without permission" item (deps, frameworks, network, hard-coded IDs, AGENTS.md non-PROJECT-INFO edits).
- The slice's CORE INTENT cannot be satisfied even with a small reframe.
- 3+ cumulative ACT deviations OR 2+ cumulative PIVOTs in the run (budgets independent; either exhausted → halt).
- Environment is broken per the Env/toolchain STOP rule.

When uncertain: lean ACT + thorough commit body, then PIVOT at the edge, then SURRENDER only when the design call genuinely belongs to the user.
